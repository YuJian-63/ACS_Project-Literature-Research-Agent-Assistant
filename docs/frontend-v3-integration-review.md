## 合并时检查结论（适配前）

前端可以构建，但统一研究流程尚不能与现有后端直接联通。以下缺口需要后续适配；构建或使用拦截响应的浏览器检查不能作为真实研究联调通过的证据。

### 1. 统一研究路由缺失

| 操作 | 新前端请求 |
| --- | --- |
| 创建 | `POST /api/v1/agent-research` |
| 列表 | `GET /api/v1/agent-research` |
| 详情 | `GET /api/v1/agent-research/{task_id}` |
| 删除 | `DELETE /api/v1/agent-research/{task_id}` |

目标后端仍提供 `/api/v1/tasks`、详情及 `/agent-result`。通过 OpenAPI 和不启动 lifespan 的 TestClient 核对，新 GET 路由实际返回 404。

来源分支的同名后端也尚未接通执行：创建接口直接返回 `503 AGENT_NOT_CONNECTED`，读写使用独立的 `AgentResearch` / `ResearchPaper` 表。因此不能只复制路由文件到目标分支。

### 2. 创建请求和响应不同

新前端发送 `{ "question": "比较这些论文的方法", "paper_ids": [], "allow_search": true }`，允许 0—20 篇参考论文，问题必填，期待 `{ "task_id": "..." }`。

现有 `TaskCreate` 要求 `task_type` 和至少一篇 `paper_ids`，对摘要、问答、综述分别限制论文数量，不接受 `allow_search`；创建响应使用 `id`。仅修改 URL 仍会校验失败。

建议增加统一研究兼容层，复用现有用户隔离、配额、幂等、派发和删除保护。接口不再要求用户提供类别或预算。先明确复用现有存储还是增加兼容迁移，不直接替换已有迁移历史。

### 3. 自动搜索需要扩展两侧派发协议

后端和 Agent 两侧的 manifest 目前都要求至少一个已选本地 PDF、`allow_search=False`，以及 `max_papers` 与来源数量一致。

还需支持仅问题任务、指定论文加外部搜索、动态资源上限，以及新搜索来源的引用校验和结果保存。Agent 核心已有搜索工具，但是否开放它仍由派发清单决定。

### 4. 详情结果需要聚合

新详情页期待顶层 `task_id`、`question`、`status`、`paper_ids`、`error`、`result`。`result` 直接包含 Agent 的 `answer`、`comparison_table`、`citations`、`sources`、`unresolved`、`stop_reason` 等字段。

现有任务详情与原生 Agent 结果分开读取。兼容层需组合任务元数据与 `AgentRun.result`；列表项则使用 `id`，并返回有序论文标题列表。失败结果及 `partial` 的原始终止原因也应保留。

### 5. 外部来源 PDF 导航需要区分

新结果组件把所有 `paper_id` 当作后端论文 UUID，导航到 `/papers?paper_id=...`。这对本地 PDF 有效；开放搜索后，arXiv 来源标识不等于数据库论文 UUID。

应选择导入外部论文并建立映射，或由前端区分本地阅读与外部 arXiv 链接；不能把 `arxiv:...` 传给要求 UUID 的论文 API。来源列表、引用对应页、返回后的引用选中状态也需一起验收。

### 6. 修改密码后的会话语义不同

V3 前端成功后提示并返回论文库，预期当前会话继续有效；现有后端会撤销会话并清除 Cookie，当前密码错误仍按旧认证失败处理。

建议成功时只保留并更新当前会话的认证版本，其他会话仍撤销；当前密码错误返回 `CURRENT_PASSWORD_INCORRECT`，同时保留限流、CSRF、用户归属和会话有效性检查。
