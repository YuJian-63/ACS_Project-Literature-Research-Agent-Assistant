# Agent 第 3.1–3.3 阶段：传输、调度与恢复闭环

## 范围与决定

- 沿用已确认方案，在当前 backend-dev-v2 工作区直接实施；不提交、不推送，不改真实环境，不启动真实模型、数据库或 TACC 作业。
- 后端负责调度、租约、输入授权和结果入库；Agent 仍通过独立 Python 解释器执行现有 run_dispatch.py，保持 persist=False。
- 新增 AGENT_TRANSPORT=manual/local，默认 manual 兼容已存在的文件交换。local 显式配置独立 Agent 解释器与项目目录。
- 适配接口覆盖上传、提交、查询与下载；本地按 dispatch 隔离目录，输入与结果原子发布。提交凭据持久化，恢复只跟踪同一作业，提交结果不明不得盲目重跑。
- 保留 status.json；业务状态仍为 queued/running/succeeded/failed。研究失败的完整 result.json 优先保存；包装器及进程失败明确结束，不伪造研究结果。
- 使用受控本地监督进程记录退出码；Worker 停止不等于取消 Agent，Agent 子进程执行设超时。缺失或冲突产物必须显式失败。

## 实施与验证

1. 先写状态与本地传输测试：严格身份/大小/JSON 校验、重复提交、进程失败与结果原子回传；观察缺少实现导致的失败，再实现。
2. 接入 Worker，保存作业标识；测试结果、包装器失败、终态缺失产物、恢复、身份冲突、租约丢失与停止行为。
3. 添加可选隔离 PostgreSQL 集成用例，验证自动派发、结果保存和重复恢复；不连接实际业务库。
4. 用独立 Agent 环境、合成 PDF 和脚本模型运行真实文件往返，禁止联网；更新 Windows/macOS 根目录相对路径操作文档。
5. 运行后端与 Agent 离线回归、相关 lint/format 和 git diff --check；记录实际结果和未执行验收。

## 范围扩展（用户要求一次性完成）

- 同轮完成 TACC 适配、重启恢复、提交不明确时的核对、超时取消、保留清理及统一验收文档。
- Ruling: 使用 TACC 官方 SDK 所依赖的 SSH/Slurm 通道，系统 OpenSSH 连接可信登录节点，由 stdlib 远程桥接调用 sbatch --parsable、squeue/sacct 和 scancel。官方旧 SDK 仅提供面向人工的输出且部分失败不返回非零退出码，不将其字符串解析作为调度协议。Windows/macOS 后端共用 SSH 接口，无需新增 Python 依赖。
- 远程配置与 Agent 模型凭据只在 TACC 上部署；后端只配置 SSH 别名、桥接程序与配置路径。Host key 校验与 BatchMode 必须开启。
- 提交前持久化 claim，作业名绑定 dispatch；重复提交返回既有作业 ID。提交回执不明时按完整作业名查询 squeue/sacct，只允许恢复唯一作业，不自动重新提交。
- Worker 重启跟踪同一 dispatch；失败或超时任务由维护循环补偿取消。清理默认 dry run，仅允许终态且超过保留时间的受控任务目录，显式 apply 才删除。
- 本轮开发验证使用脚本模型、假 SSH/Slurm 与隔离临时目录；不宣称真实 TACC、macOS 或模型验收完成，不修改真实环境，不执行数据库迁移。
