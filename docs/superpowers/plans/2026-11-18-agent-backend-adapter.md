# Agent 主导的后端适配计划

**目标**：后端负责用户隔离、任务派发、原始 PDF 交付与结果持久化，研究执行以 `agent/schemas.py` 的 Task/TaskResult 为准。

**范围**：本轮只修改后端与接口文档；不启动服务、不迁移用户数据库、不提交 TACC 作业、不调用模型、不修改 Agent 算法。按用户要求，适配代码完成后再运行离线测试。

## 架构决定

- 新增显式 `TASK_RUNNER=agent`；保留 mock/langgraph 以读取历史与兼容既有部署，agent 模式绝不回退到旧检索、生成或证据算法。
- 传输边界采用版本化文件交换协议。后端原子发布只含任务 JSON、来源清单和授权 PDF 的输入包，接收带 dispatch_id 与输入摘要的完整结果信封。TACC 上传、作业提交与下载由后续传输桥接完成，本轮不猜测 SDK 命令。
- Agent Task 保持严格字段；task_type 转成 question 的任务说明；运行环境与来源文件映射放在清单中。禁用自动联网搜索，仅允许选定论文。
- 原始上传即可派发，不依赖后端 PaperChunk；以文件大小和 SHA-256 绑定资料。Agent 尚需增加本地 PDF 来源解析，这一依赖明确记录，不能声称已完成端到端执行。
- 每个任务保留一个稳定 dispatch_id；租约丢失重领继续等待同一输入包，避免隐式再次提交。迟到结果仅由仍拥有任务的 Worker 接收，失效或超时任务不覆盖。
- 保存完整 Agent 结果。completed/partial 可展示；其他 stop_reason 明确失败并保留诊断。Markdown 比较表保留原样，不强转旧表格 schema。引用映射回用户原始 PDF 页码，不伪造旧 UUID chunk。
- 旧接口继续返回可阅读 Markdown 与 Cn 引用；新增原生 Agent 结果接口和停止原因。Agent 的每次输出上限与总 Token 用量分开，不能假称 Agent 已支持累计 Token 预算。

## 核查重点

输入包不得含密钥或其他用户文件；输入变化必须拒绝；重复导出和结果回放幂等；部分结果不能伪装完整；原生引用不得经过旧逐字片段校验；旧任务与 mock 行为保持兼容。

## 后续依赖

后端接口适配已实现，但端到端链路尚未打通：Agent 仍需支持 local: 来源及本地 PDF 清单，TACC 仍需实现实际传输、提交、状态协调与结果下载。默认保持 Agent 派发关闭，不把文件交换层表述为可直接运行的 TACC 集成。
