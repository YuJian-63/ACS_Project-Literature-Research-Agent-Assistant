# 用户账号、邮箱恢复与个人资源隔离设计

日期：2026-11-14。状态：用户已批准实施；用户另行授权清除本项目全部旧业务数据。暂不提交 Git。

## 1. 需求与解释

原项目是受信本机单用户应用。当前 papers、tasks、paper_imports 没有用户归属，详情和 PDF 直接按 ID 查询，任务幂等键和 arXiv 版本导入身份为全局唯一。前端已有中英文界面、自动综述预算及来源证据联动，必须保留。

用户要求不同用户拥有不同论文库，允许公开注册和密码找回；曾改为用户名＋密码注册，随后选择“还是通过邮箱吧”。本稿按“保留用户名＋密码登录，注册填写邮箱，邮箱验证和找回密码”解释；邮件由已选定的 QQ 邮箱 SMTP 发出。QQ 只是系统发件服务，用户可使用自己的有效邮箱，不限 QQ 邮箱。

目标：公开注册、验证邮箱、登录/退出、找回/修改密码，以及论文/文件/导入/任务/研究结果的完整隔离。非目标：第三方登录、团队共享、公开论文库、账号删除、自助更改邮箱/用户名、管理员 Web 后台和恢复码。

## 2. 方案取舍

- 项目内账号＋可撤销数据库会话＋QQ SMTP：本稿建议。复用 FastAPI/PostgreSQL 和同源代理，不增加外部身份平台；项目负责验证、邮件和隔离。
- 托管身份平台：减少自建认证代码，但需要额外平台配置、回调和部署约束；当前未选择。
- 无邮箱＋恢复码：此前提出，用户改选通过邮箱恢复，本稿不采用。

数据库会话取代长期浏览器 Bearer Token；同源部署是第一版的支持边界。下面的时限、限流和字段细则属于本稿提出的默认值，可由实施者调优，产品范围保持不变。

## 3. 用户流程

### 注册与邮箱确认

注册页填写用户名、邮箱、密码、确认密码。用户名为 3–32 个 ASCII 字母、数字或下划线，大小写不区分，保存显示值和规范键；保留系统用户名。邮箱去除首尾空白、校验格式，应用内按小写键唯一，不自行删除点号或加号后缀。密码 15–128 个字符，允许中文、空格、粘贴和密码管理器，不自动 trim，不要求复杂字符组合，不保存明文。

注册先创建 pending 用户，不能访问业务资料。pending 占位最多 24 小时；同一用户名或邮箱不会被后续公开注册覆盖密码。冲突统一返回“该注册信息不可用”；可走重新发送验证或重新填写。到期 pending 仅在没有业务资源、会话且不是旧数据账号时清理。

验证邮件包含注册用户名及 24 小时有效的一次性链接。GET 打开只显示确认页，必须 POST 提交令牌和注册时设置的密码才能激活；邮件扫描器不会激活账号。额外验证密码可避免他人代填邮箱后，收件人误点链接激活他人已知密码的账号。链接无效/过期时可重新发信，重新发信不改原注册密码。激活后回到登录，不自动建立会话。

### 登录和退出

用户名＋密码登录，账号须已验证且未停用。错误凭据统一提示；仅在已校验正确密码后提示邮箱待验证。成功登录创建全新的会话，服务端撤销/过期后立即不可用。当前会话最长 7 天，不支持自动续期和“记住我”。退出通过 POST 撤销当前会话并清除 Cookie。

### 忘记与重置密码

找回页输入邮箱，存在、未注册、未激活和账号停用的邮箱均返回相同受理提示；只有 active 账号安排重置邮件。邮件 30 分钟有效，重发产生新令牌并撤销该目的的旧令牌。重置页填写新密码和确认密码。令牌消费、密码替换、同用途令牌撤销及全部登录会话撤销必须在同一事务内完成。不得自动登录，成功后返回登录页。

重置接口不要求旧会话，重置失败不可消耗仍有效的令牌。两个并发重置请求只能有一个成功。登录状态下修改密码要求当前密码，同样撤销全部会话后重新登录。不使用安全问题、公开用户资料或用户名本身验证找回身份。

## 4. 数据模型

新增五类记录，均使用数据库时间计算失效和限流。

| 表 | 主要内容及约束 |
| --- | --- |
| users | UUID；username/username_key；email/email_key；password_hash；status(pending/active/disabled/legacy_locked)；email_verified_at；auth_version；创建/更新时间。用户名、邮箱规范键唯一；旧数据账号允许邮箱/密码为空且禁止登录，普通账号不得为空 |
| auth_sessions | user_id；随机会话令牌摘要唯一；auth_version；expires_at、revoked_at、created_at。查询必须同时校验用户 active 和当前 auth_version |
| auth_email_tokens | user_id；purpose(verify_email/reset_password)；随机令牌摘要唯一；expires_at、consumed_at、revoked_at。消费时锁定用户及令牌，校验用途/状态/时间；重发与消费锁序一致 |
| auth_mail_outbox | user_id、token_id；模板/语言；加密邮件载荷；queued/sending/sent/failed；attempt、next_attempt_at、租约、错误分类。成功或永久结束后清除敏感载荷 |
| auth_rate_buckets | 作用域、目标键、时间窗口、计数及失效时间；数据库原子计数，支持 API 多进程共享；过期清理 |

密码使用 Argon2id；具体实现库及参数在实施计划中锁定并基准验证，不自写密码学。会话和邮件令牌使用独立的至少 256 bit 安全随机值；摘要只用于高熵令牌，不能代替密码哈希。

papers、tasks、paper_imports、paper_sources 增加非空 user_id。增加 papers(id,user_id)、tasks(id,user_id) 复合唯一约束；TaskPaper 增加 user_id，复合外键同时关联任务和论文，保留原 paper_sha256 快照外键，禁止跨用户任务选文。PaperSource 和 PaperImport 通过 (paper_id,user_id) 引用同归属论文，失败/排队导入允许 paper_id 为空。

删除旧全局唯一约束，替换为 tasks(user_id,idempotency_key)、paper_imports(user_id,provider,external_id)、paper_sources(user_id,provider,external_id)；保留 paper_id 的一对一约束。不同用户可独立导入同一版本，得到各自 Paper 和文件；本期不跨用户去重存储。

片段、事件、产物、引用和综述检查点沿现有论文/任务关系继承归属，不盲目给每张表重复添加 user_id。产物引用只允许该任务已绑定的同用户论文。保留并测试已有约束与 Worker 租约。

## 5. 登录态与请求边界

生产使用 HTTPS、同源 /api 代理、HttpOnly/Secure/SameSite=Lax、Path=/、无 Domain 的会话 Cookie。本地 HTTP 使用单独的明确开发配置和 Cookie 名，启动时禁止生产配置降级。前后端统一 localhost 或统一 127.0.0.1，不能混用。

非 GET 的浏览器请求校验精确 Origin，拒绝缺失或不受信 Origin；认证接口仅接收 application/json，不接收 form 编码。已登录变更请求额外要求绑定当前会话的 X-CSRF-Token；使用独立 AUTH_CSRF_KEY 对当前原始随机会话令牌计算 HMAC，常量时间比较，不在数据库保存可恢复的会话令牌。GET /auth/me 根据当前 Cookie 重建并返回 CSRF Token 与用户，响应 Cache-Control:no-store。首次登录/注册/忘记密码由 Origin、JSON、限流及只允许受信来源的 CORS 保护，登录不得沿用客户端指定的会话 ID。

GET /health、/ready 保留不含账号和私有数据的健康响应。未登录业务 API 返回 401；有效用户访问其他用户/不存在资源均返回 404。邮箱未激活不发业务会话。密码错误不暴露用户状态。所有账户/私有响应 no-store，不允许共享代理缓存 PDF 或任务响应。

PDF 仍经已认证的后端文件接口流式返回，打开新标签页自动携带同源 Cookie；存储目录不作为静态资源公开。文件下载同样验证用户，禁止用 URL 中的 user_id 授权。

## 6. 接口草案

| 方法与路径（统一 /api/v1 前缀） | 输入与行为 |
| --- | --- |
| POST /auth/register | username/email/password；确认密码由前端校验；返回 202 受理，不登录 |
| POST /auth/verify-email | token/password；原子消费，返回激活成功 |
| POST /auth/resend-verification | email；统一 202；pending 有效时发新令牌 |
| POST /auth/login | username/password；成功设置会话 Cookie，返回 user 和 CSRF Token |
| GET /auth/me | 返回 id/username/email 与 CSRF Token；不返回摘要、内部密钥和会话令牌 |
| POST /auth/logout | 当前会话＋CSRF；撤销并清除 Cookie |
| POST /auth/forgot-password | email；统一 202，异步邮件 |
| POST /auth/reset-password | token/password；原子重置并撤销全部会话 |
| POST /auth/change-password | 当前会话、CSRF、current_password/password；更新后重新登录 |

业务请求体不增加可信 user_id 字段；后端从认证依赖传入 user_id。注册/重发/找回响应只表示已受理，不声称 SMTP 已送达。校验、邮件受理、限流和业务错误沿用现有 error/code/details 与请求编号协议。

## 7. 资源隔离与后台处理

所有列表查询、count、状态筛选、分页、详情、PDF、导入重试、任务重放、事件和产物读取统一限定当前用户。ID 访问使用“ID＋user_id”查询，不先返回全局存在性。创建任务先在同一事务校验全部 paper_ids 属于当前用户且满足原就绪规则，再校验/复用该用户幂等键。

arXiv 公共元数据缓存和 source_request_gates 继续全站共享；在返回响应时才叠加本人的导入状态，不把用户状态写入共享缓存。Worker 根据持久化资源的 user_id 创建对应论文和来源；不能从外部请求或网络元数据决定归属。下载/解析/研究 Worker 可内部调度多用户资源，租约 owner_id 仍是进程令牌，不能与用户 ID 混用。

身份变更后：终止进行中的前端查询和轮询，清空旧用户列表/结果/选文/提交幂等键和 CSRF 内存，递增请求身份版本忽略旧响应，并回到登录页；跨标签页用 BroadcastChannel 或 storage 通知重新检查会话，不广播秘密。界面语言可继续保留。已在后台运行的合法任务不因退出而取消。

新增默认每用户最多 2 个 queued/running 研究任务、2 个 queued/running 导入；每用户每日新建研究任务默认 20 个，幂等重放不重复计数。额度为服务端配置并在数据库事务中原子判断，不让用户设置综述预算；已有单任务自动预算、全站 arXiv 冷却继续生效。这些是起始保护值，不代表 QQ 或模型供应商配额。

## 8. 邮件发送与配置

QQ SMTP 使用 smtp.qq.com:465 的隐式 TLS，校验证书，身份为完整发件邮箱，凭据为 SMTP 授权码；不使用 QQ 登录密码。发件人与 SMTP 用户一致。收件人可为其他服务商邮箱。生产链接只由固定的 FRONTEND_PUBLIC_URL 生成，不能信任请求 Host 或客户端传入的重定向地址。

验证、重置链接把令牌放 URL fragment；独立页面提取到内存后清除地址中的令牌，不加载第三方脚本、字体或统计资源，设置 Referrer-Policy:no-referrer。GET 不消费；用户确认后 POST。邮件模板仅含必要身份信息、用途、有效期和非本人操作提示；使用 UI 语言并对用户名转义。

用户/令牌/发信 outbox 在同一事务创建；独立 mail_worker 从 PostgreSQL 按租约领取，SMTP 连接和总尝试设超时。可重试错误按 30 秒、2 分钟退避，含首次最多 3 次发送，超令牌失效时间停止；证书/认证错误不无限重试。可能重复投递同一封，但只允许一次消费令牌。重发撤销旧令牌；Worker 发送前校验令牌状态，过期链接即使已发送也无效。

为支持进程重启后继续发信，outbox 使用独立 MAIL_OUTBOX_KEY 进行带认证加密，仅 Worker/API 可解密；不记录明文令牌、完整重置链接、密码或授权码。发送结束删除加密载荷，保留无秘密的状态和错误类型。密钥丢失时停止发送，撤销相关未完成令牌并引导用户重发；不能将密钥保存在数据库或仓库。

初始限流：发信同邮箱间隔至少 60 秒、每小时最多 5 次，IP 每小时最多 20 次，全站每小时最多 100 次；登录按 IP 与规范用户名分别限制，不永久锁号；注册、令牌消费及修改密码也有独立限制。具体登录桶默认 IP 30 次/分钟、用户名 10 次/15 分钟，验证/重置令牌尝试每 IP 30 次/15 分钟。使用数据库多进程共享计数，网络代理只接受明确配置的受信代理来源，不能盲目信任 X-Forwarded-For。

新增配置：FRONTEND_PUBLIC_URL、AUTH_COOKIE_SECURE、AUTH_SESSION_TTL_SECONDS、AUTH_VERIFY_TTL_SECONDS、AUTH_RESET_TTL_SECONDS、AUTH_RATE_KEY、AUTH_CSRF_KEY、SMTP_HOST、SMTP_PORT、SMTP_USERNAME、SMTP_AUTH_CODE、SMTP_FROM、SMTP_TIMEOUT_SECONDS、MAIL_OUTBOX_KEY 及用户额度。邮件凭据使用 SecretStr，沿用 backend/.env 的本地加载方式并给 .env.example 添加无秘密占位值。生产启动缺少邮件配置时不开放注册/找回；已有 active 用户登录和私有业务不因暂时 SMTP 故障不可用，邮件 Worker 报告降级状态。

## 9. 数据清理与切换（以本段最新授权为准）

2026-11-14 用户批准先清除全部旧数据，不再迁移或认领旧资料。先核验配置中的本项目数据库与受控存储目录，停止相关服务；只清空业务表与本项目生成文件，保留 schema/alembic_version。迁移遇到非空旧业务表时拒绝升级，要求先完成清理，不在 Alembic 中隐式删除数据。空库建立严格非空归属，不创建默认或历史资料账号。

当前工作区位于 main，按现有授权在当前工作区实施，不自动创建分支、提交或推送。不在迁移脚本中写默认密码、真实邮箱或 SMTP 授权码，不开放无认证的兼容旧接口，不将带用户数据直接降级回匿名模式。

## 10. 前端与验收

新增登录、注册、等待验证、邮箱确认、忘记密码、重置密码和修改密码界面，使用现有工作台视觉和中英文。表单包含等待/失败/重发倒计时，显示“请求已受理”而非“邮件一定已送达”。业务路由先等待 /auth/me；401 时清理状态，安全保留站内返回路径（不接受外部地址）。账号菜单显示真实用户名并提供修改密码与退出入口，不新增用户管理后台。

必须通过：

1. 账号：注册唯一键并发、规范化、密码校验、pending 到期清理、错误凭据统一响应、验证只消费一次及邮件扫描 GET 不激活；他人预注册邮箱不被误激活。
2. 邮件/恢复：不存在邮箱统一响应、重发撤销、到期、并发重置一个赢家、重置失败回滚、全会话撤销、登录和重置竞争不产生可继续使用的旧会话；加密 outbox 重启/租约/重试/失效链接和不泄露秘密。
3. 双用户：A/B 的论文列表和数量、PDF、导入历史、搜索已导入状态、任务/事件/产物/引用互不串用；混选论文请求整笔拒绝；相同幂等键互不影响，同用户重放仍有效；相同 arXiv 版本可分别导入。
4. Worker：下载来源继承归属，Parser/Research 正常处理；继续通过原并发幂等、租约栅栏、共享来源许可和 staged review 测试。
5. 登录态：Origin、JSON、CSRF、Cookie 生产/开发配置、退出、过期、多标签页及切号旧响应抑制；PDF 新标签页正常；所有私有数据请求均鉴权。
6. 迁移与清理：非空旧库拒绝升级且保持原状；清理默认预览，校验数据库与目录、拒绝活跃连接和未知存储文件，仅清理本项目业务表与生成文件并保留 schema/alembic_version；空库升级后模型不漂移。
7. 现有页面、自动预算、双语和响应式回归通过。离线邮件夹具/SMTP 替身为默认测试；真实 QQ 邮件和原生 PostgreSQL 的双用户验收单列，不用真实邮件批量跑回归。
