# MVP-1A：真实 PDF 解析与证据准备

用户确认范围：独立 Parser Worker、真实文本型 PDF 解析、物理页码片段、失败/超时/失联恢复、前端状态衔接及 Agent 读取边界。不实现 OCR、搜索、模型调用或 LangGraph。

## 设计

- 沿用 papers 的解析租约和 paper_chunks，无新迁移和公开 API。Worker 显式启动才领取 uploaded，未启动时保留现有 Mock 上传流程。
- pypdf 7.x 在可终止子进程中读取受控文件，核对大小/hash，拒绝加密、损坏、空页数和全文无可提取文本；空白页不生成虚构片段，物理页码不压缩。逐页原始提取文本只清理空字节/换行，不跨页拼接，分为最多 2000 字符的连续片段，无重叠、不截断全文。
- 默认限制：500 页、8 MiB 文本、10000 片段、单页解压内容流 16 MiB、120 秒子进程执行时间。超限明确失败，不以部分结果冒充成功。解析子进程不接收 DATABASE_URL、STORAGE_ROOT 等后端进程环境变量，但它仍以 Worker 的 OS 用户运行，不是完整沙箱。
- 短事务使用 SKIP LOCKED 领取；租约 60 秒、20 秒续租。子进程执行期间父进程检查停止/超时/所有权，失去所有权即终止子进程。独立 Worker 恢复过期 processing 为 failed，不自动重跑；旧 Worker 不能追加结果。
- 完成时锁定论文并核验所有权、源 hash 与结果版本，chunks、页数、版本及 ready 一次提交；失败不保留半套片段。不删除/覆盖已有 chunks，不重解析 ready/failed，升级或重试需重新上传生成新 ID。
- 首次为已有 Mock 任务引用的 uploaded 论文追加解析元数据是允许的：原文件、hash、历史任务和已有片段均不改写。Mock 不消费新片段或变成真实任务。
- Agent 在应用内通过 evidence 服务按 ready paper_id 加载有界分页片段，获得 chunk_id、物理页码、文本 hash 和解析版本。只读取，不对外暴露存储路径；真实 Runner 及引用结果校验另阶段实施。
- 前端论文库和选择器按每轮完成后 2 秒查询可见 uploaded/processing 记录，终态停止；错误保留数据可重试；解析失败原因与页数/版本可查看。选中后状态变化仍以提交时服务端校验为准。

## 验收

临时脚本保留在忽略的 runtime，不添加发布测试框架。覆盖有效多页/空白页/长文本、坏文件/加密/无文本/超限、原文件核验、原子回滚、租约过期/陈旧写回、子进程超时及停止、证据只读分页、现有 Mock 回归、真实 API/Parser 浏览器流程。当前 Docker 不可用，PGlite 仅作兼容验收，不声称原生 PostgreSQL 多连接竞争通过。无自动 Git 提交/推送。
