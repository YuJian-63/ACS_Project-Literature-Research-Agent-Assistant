# Research and evaluation limits

Agent research receives `min(AGENT_MAX_STEPS, 32 + 8 * N)` steps. `N` is the selected paper count, plus `AGENT_SEARCH_MAX_PAPERS` when search is enabled, capped at 20. `AGENT_MAX_STEPS` defaults to 200 and accepts values from 1 to 200. Both unified research and legacy summary/QA/review submissions use this policy. A single selected paper without search receives 40 steps; five receive 72; twenty receive 192. Task duration keeps its existing policy.

`AGENT_OUTPUT_TOKENS` defaults to 16384 and accepts values from 1024 to 32768. Unified research and legacy summary/QA/review tasks use `min(AGENT_OUTPUT_TOKENS, AGENT_CONTEXT_TOKENS - 2048)` as the main model's per-request output budget, independent of paper count. This is a ceiling, not a requested output length or a task-wide token allowance; auxiliary model calls can use smaller budgets. The Agent reserves this output budget when preparing model context. At least 2048 tokens remain available for input, but evidence-heavy tasks may need substantially more input space.

TACC and custom course-model submissions additionally cap the effective context window at 36864 tokens, matching the bundled model service configuration. Their output budget is `min(manifest output budget, 16384, effective context window - 2048)`, replacing the old 4096-token ceiling. The default `AGENT_CONTEXT_TOKENS=32000` is unchanged. A configured output budget of 16384 therefore leaves a planned input budget of 15616 tokens; increasing output reduces the space available for evidence and conversation history. These are budgeting limits, not an exact tokenizer guarantee. A fixed output limit cannot guarantee that arbitrarily long answers finish; `finish_reason="length"` still produces `output_truncated` rather than treating incomplete JSON as a successful result.

`USER_DAILY_TASKS` defaults to 50 newly created research tasks per user per UTC day. Idempotent replays do not create tasks or consume additional allowance. The existing active-task limit is independent. Research allowance still counts existing task records; deleting research history can reduce its daily count.

DeepSeek scoring defaults to `EVALUATION_TIMEOUT_SECONDS=180`, `EVALUATION_DAILY_LIMIT=50` and `EVALUATION_EVIDENCE_TIMEOUT_SECONDS=60`. All distinct cited original pages are eligible for extraction; there is no page-count setting. PDF identity verification, subprocess isolation and memory/byte/input/output budgets still apply. See [evaluation operations](deepseek-evaluation.md) for retries, evidence limitations and the independent evaluation allowance.

## Applying the settings

1. Update any explicit values in the private backend `.env`; environment values override these defaults. Remove the obsolete `EVALUATION_MAX_ORIGINAL_PAGES` line.
2. Run `alembic upgrade head` and `alembic check` from `backend/` before enabling tasks above 100 steps. Revision `20261122_0015` raises the database constraint to 200 and preserves existing task budgets. Downgrade to 0014 is rejected while tasks above 100 steps exist; no historical budgets are silently rewritten.
3. Restart the API, research worker and evaluation worker using the same configuration.

For the larger output budget, explicitly replace any old `AGENT_OUTPUT_TOKENS=8192` value in the private backend `.env` with `AGENT_OUTPUT_TOKENS=16384`; an explicit old value overrides the new default. Deploy the updated backend code as well, because an older TACC submission path will still cap output at 4096. Restart `acs-api.service` and `acs-runner.service` to reload settings. This output-budget change requires no database migration and takes effect only for new tasks; existing signed dispatch manifests retain their original limits. Failed tasks must be submitted again. This setting is independent of DeepSeek's `EVALUATION_MAX_OUTPUT_TOKENS` and `EVALUATION_MAX_INPUT_BYTES`.

New research submissions receive the new step budgets. Existing tasks keep their saved budgets. Evaluation settings are versioned: an old queued configuration is rejected with `EVALUATION_CONFIG_CHANGED`; explicitly request a new evaluation version after changing these settings. The old 12-page extraction cap is removed even when private configuration still contains its obsolete setting.
